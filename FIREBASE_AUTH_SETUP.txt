1. IS FIREBASE FREE?
================================================================================
YES! Firebase has a 100% FREE tier ("Spark Plan").
- Free Realtime Database: 1 GB stored data, 10 GB/month download, 100 simultaneous connections (plenty for private rooms!).
- Free Authentication: Unlimited Anonymous users, 50,000 monthly active users for Google/Email.
- No credit card required for the Spark plan.


================================================================================
2. STEP 1: CREATE A FIREBASE PROJECT
================================================================================
1. Go to the Firebase Console:
   https://console.firebase.google.com/

2. Click "+ Add project" (or "Create a project").
3. Enter a project name (for example: "day-room-private" or "my-day-room").
4. (Optional) Disable Google Analytics for simplicity, or leave it enabled.
5. Click "Create project" and wait a few seconds until it's ready.
6. Click "Continue".


================================================================================
3. STEP 2: REGISTER A WEB APP & GET CONFIG KEYS
================================================================================
1. On your project's overview page, click the Web icon (</>) to add a web app.
2. Enter an App nickname (e.g., "Day Room Web").
3. Uncheck "Also set up Firebase Hosting" (since you can host on Vercel/GitHub Pages).
4. Click "Register app".
5. You will see a firebaseConfig object like this:

   const firebaseConfig = {
     apiKey: "AIzaSyD-EXAMPLE-KEY-HERE",
     authDomain: "your-project-id.firebaseapp.com",
     databaseURL: "https://your-project-id-default-rtdb.firebaseio.com",
     projectId: "your-project-id",
     storageBucket: "your-project-id.appspot.com",
     messagingSenderId: "123456789012",
     appId: "1:123456789012:web:abcdef123456"
   };

   Note: If databaseURL is not visible yet, don't worry! It is generated
   in the next step when you create the Realtime Database.


================================================================================
4. STEP 3: ENABLE FIREBASE REALTIME DATABASE
================================================================================
1. In the left-hand navigation sidebar under "Build", click "Realtime Database".
2. Click the "Create Database" button.
3. Select a Realtime Database location (e.g., "United States (us-central1)" or closest to you).
4. Click "Next".
5. For Security rules, select "Start in test mode" (or "Start in locked mode").
6. Click "Enable".
7. Look at the top of the Realtime Database page for your database URL:
   It looks like: https://your-project-default-rtdb.firebaseio.com/
   Make sure this URL is in your firebaseConfig.databaseURL.


================================================================================
5. STEP 4: ENABLE FIREBASE AUTHENTICATION
================================================================================
1. In the left-hand navigation sidebar under "Build", click "Authentication".
2. Click the "Get started" button.
3. Go to the "Sign-in method" tab.

CHOOSE YOUR AUTHENTICATION METHOD:

Option A: Anonymous Authentication (RECOMMENDED FOR DAY ROOM)
-------------------------------------------------------------
Why Anonymous Auth?
- Day Room is designed as a frictionless, private space for two people.
- Anonymous Auth automatically creates a unique, cryptographically secure Firebase Auth UID in the background without asking users for passwords or emails.
- It satisfies all auth != null security rules in Firebase.

How to enable:
1. Click on "Anonymous" in the provider list.
2. Toggle the switch to "Enable".
3. Click "Save".

Option B: Email/Password (Optional)
-----------------------------------
1. Click on "Email/Password" in the provider list.
2. Toggle the first switch ("Email/Password") to "Enable".
3. Click "Save".

Option C: Google Sign-In (Optional)
-----------------------------------
1. Click on "Google" in the provider list.
2. Toggle "Enable".
3. Select your project support email.
4. Click "Save".

6. STEP 5: CONFIGURE DATABASE SECURITY RULES
================================================================================
1. In the left sidebar, click "Realtime Database" -> "Rules" tab.
2. Paste ONE of the following rule configurations:

---
RULE SET A: With Firebase Auth (Anonymous or User Logged In)
Use this if you enabled Anonymous Auth in Step 4.
---
{
  "rules": {
    "rooms": {
      "$roomId": {
        ".read": "auth != null",
        ".write": "auth != null"
      }
    }
  }
}

---
RULE SET B: Simple Link-Based Access (No Auth Required)
Use this if you want anyone with the unguessable 12-character random room URL to access the room directly without Firebase Auth.
---
{
  "rules": {
    "rooms": {
      "$roomId": {
        ".read": true,
        ".write": true,
        ".validate": "newData.hasChildren(['users']) || data.exists()"
      }
    }
  }
}

3. Click the "Publish" button at the top right of the editor.

7. STEP 6: ADD CREDENTIALS TO DAY ROOM
================================================================================
Open js/firebase-config.js in your code editor.

Replace the placeholder credentials with your actual values:

const firebaseConfig = {
  apiKey: "YOUR_ACTUAL_API_KEY",
  authDomain: "your-project-id.firebaseapp.com",
  databaseURL: "https://your-project-id-default-rtdb.firebaseio.com",
  projectId: "your-project-id",
  storageBucket: "your-project-id.appspot.com",
  messagingSenderId: "YOUR_MESSAGING_SENDER_ID",
  appId: "YOUR_APP_ID"
};

Quick Tip: You can also paste your config directly in the browser when opening
the Day Room landing page using the "Configure in browser" button on the banner!

8. STEP 7: HOW AUTHENTICATION WORKS IN CODE
================================================================================
Day Room includes the Firebase Auth SDK:
<script src="https://www.gstatic.com/firebasejs/10.8.0/firebase-auth-compat.js"></script>

When you initialize Firebase with Anonymous Auth enabled, Day Room automatically
calls:
firebase.auth().signInAnonymously()
  .then((userCredential) => {
    console.log("Signed in anonymously as:", userCredential.user.uid);
  })
  .catch((error) => {
    console.error("Auth error:", error);
  });

This guarantees that:
1. Every browser session receives an official Firebase Auth token.
2. Firebase Database rules requiring auth != null succeed seamlessly.
3. Two different devices/browsers will each have their own authenticated session.

9. STEP 8: DEPLOYING TO VERCEL (REALTIME MULTI-DEVICE TESTING)
================================================================================
Day Room is a pure static web app (HTML + CSS + Vanilla JS).

Deploying with Vercel CLI:
1. Open PowerShell or Terminal in the project folder:
   cd c:\Users\hp\OneDrive\Desktop\Taskmirrorforakshat
2. Run:
   npx vercel
3. Follow the simple prompts (Set up and deploy? Yes -> Link to existing? No -> Project name -> default settings).
4. Vercel will give you a live production URL (e.g. https://day-room.vercel.app).

Testing Realtime Sync:
1. Open the deployed website on Device 1 (e.g., your laptop).
2. Click "+ Create a room".
3. Copy the room link (e.g., https://day-room.vercel.app/room.html?room=8fK2xPq91Lm).
4. Send the link to Device 2 (e.g., your phone or a friend's device).
5. Device 1 enters name (e.g., "Akshat") -> starts a timer.
6. Device 2 enters name (e.g., "Companion") -> immediately sees Akshat's live timer counting upward!
7. Device 2 logs "Water consumed" -> Device 1 sees it instantly without page refresh!
8. Device 2 leaves a note "have a great focus session" -> appears in real time!

10. TROUBLESHOOTING & FAQ
================================================================================
Q: I see "Permission Denied" in the browser console.
A: Check Step 5. If your rules require auth != null, ensure you enabled "Anonymous" auth in Firebase Authentication (Step 4) OR change rules to .read: true, .write: true.

Q: Where do I find databaseURL if it's missing from my config?
A: In Firebase Console -> Build -> Realtime Database. The URL displayed at the top of the Data tab (e.g., https://my-app-default-rtdb.firebaseio.com) is your databaseURL.

Q: Is data stored locally or in Firebase?
A: All shared room data (users, timers, logs, messages) is stored directly in Firebase Realtime Database. LocalStorage is only used to remember the local display name.
